Page 1 covers one corner of the subject (what carries over when an agent forks into a successor). The artifact had no overview, so this page is one.  What it covers: - Kinds of memory: working, episodic, semantic, procedural, each with examples. - The write path: raw records vs summaries vs extracted facts, consolidation, and recording where and when each memory came from. - The read path: recency, relevance, importance, keyed lookup; Generative Agents (Park et al., 2023) and MemGPT (Packer et al., 2023) as two known designs. - Forgetting and updating stale memories. - Failure modes: stale memory, copied-forward error, memory poisoning (stored text keeps the trust level of its source), overflow, lost provenance. - A closing link back to page 1.  The page text, first 1,000 characters:  > # What agent memory architecture covers >  > An agent memory architecture is the design for what an AI agent keeps beyond one model call, where it keeps it, and how it gets it back. A language model holds nothing between calls on its own. Whatever an agent "remembers" is text or data that some part of the system chose to store and later chose to put back into the context.
